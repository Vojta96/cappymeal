# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm start                                   # Dev server on port 3000
npm run build                               # Production build (output: build/)
npm test                                    # Jest in watch mode
npm test -- --watchAll=false src/App.test.js  # Run a single test file once
node scripts/gen-icons.js                   # Regenerate PWA icons from src/Images/Cappy.png
npm test -- --watchAll=false -t "name"      # Run tests matching a name
npm run test:rules                          # RTDB rules tests (Database emulator, needs Java)
cd functions && npm test                    # Cloud Functions unit tests (node:test)
```

There is no separate lint script; ESLint (`react-app` config) runs inside `npm start` / `npm run build`.

Tests never touch real Firebase: `src/App.test.js` covers the pure helpers in `src/lib/` (`src/lib/quantity.test.js` covers amounts / packages and the product-selection helpers in `src/lib/shop.js`), `src/screens/screens.test.js` smoke-renders every screen with a fake `HouseholdContext` value and mocked `firebase`/`services`. CRA sets `resetMocks`, so mock factories use plain functions, not `jest.fn`. `CI=true npm run build` treats ESLint warnings as errors.

Deploy (only on the owner's explicit request), always in this order: `firebase deploy --only functions`, then `firebase deploy --only database`, then `npm run build && firebase deploy --only hosting` (new clients need the callables; the rules block the old client-side writes). The only secret is `ROHLIK_ENC_KEY` (`firebase functions:secrets:set ROHLIK_ENC_KEY`, value = base64 of 32 random bytes; changing it makes every stored Rohlík token unreadable, households then have to reconnect). For the emulators put it in `functions/.secret.local` (never commit it).

## Stack

- **React 18** (JavaScript, not TypeScript) via Create React App; **React Router v6** (`BrowserRouter` in `src/index.js`)
- Plain CSS, no UI library: design tokens in `src/styles/tokens.css`, shared components in `src/styles/ui.css`, one CSS file per screen. Fonts Manrope + Instrument Serif and Material Symbols Rounded icons are loaded from Google Fonts in `public/index.html` (`<Icon name="..."/>` in `src/components/ui.js`).
- **Firebase** (project `cappymeal-go`): Auth, Realtime Database (europe-west1), Cloud Functions (europe-west1, Rohlík + reminders, in `functions/`), Messaging, Hosting. `src/firebase.js` exports `app`, `db`, `auth`, `functions`; callables go through `callFunction` in `src/services/functions.js`.
- Mobile-first PWA: `public/manifest.json`, icons generated by `scripts/gen-icons.js`, iOS safe areas via `env(safe-area-inset-*)`.
- Responsive: < 521px phone; 521–1023px the phone layout in a centered 480px column; **>= 1024px desktop** – left sidebar (`Sidebar` in `AppLayout.js`) instead of the tab bar, wide multi-column screens, bottom sheets shown as centered modals, push banner as a top-right toast, split login/onboarding (`AuthLayout`). Mostly CSS (`@media (min-width: 1024px)` blocks at the end of each CSS file, `.only-mobile` / `.only-desktop` helpers, `display: contents` wrappers); `useIsDesktop()` from `src/hooks/useMediaQuery.js` is used only where the component tree differs (AppLayout, Home, Plan week grid, RecipeDetail, Cart side panel). Changes to the phone layout must keep both variants working.

UI text and recipe data are in Czech.

## Architecture

The shared data model (RTDB layout, day statuses, Cloud Function APIs) is documented in the redesign contract; the essentials are below.

- `src/screens/` – one component per route; `src/components/` – AppLayout (tab bar, banner), BottomSheet, Thumb (recipe photo/emoji), PushBanner; `src/context/` – Auth and Household; `src/lib/` – pure logic (dates, meals, join codes, image resize); `src/services/` – Firebase-touching helpers (`household.js` onboarding; `rohlik.js` and `push.js` are client wrappers for the Cloud Functions / FCM).

### Routing and gating (`src/App.js`)

`AuthProvider > Gate`. Logged out → only `/login`. Logged in but `users/{uid}.householdId` empty → only `/household` (create a household or join with an 8-char code). Otherwise `HouseholdProvider > BannerProvider > AppLayout` with `/`, `/plan`, `/recipes`, `/recipes/new`, `/recipes/:id`, `/recipes/:id/edit`, `/cart`, `/cart/done`, `/notifications`, `/settings`. The tab bar is hidden on `/recipes/:id*`. `/notifications` (Upozornění) is only the notifications list; `/settings` (Nastavení, `src/screens/Settings.js`) holds the cards Domácnost (name for the owner, join code + share + new code, members with remove for the owner), Účet Rohlík, Připomínky (toggles, hour, push enable + iPhone hint) and Účet (logout). Entry points: the household block at the bottom of the desktop sidebar (a link to `/settings`, logout lives only in Settings), the gear button in the Přehled header and on Upozornění (mobile), and a card on Upozornění.

### Auth (`src/context/AuthContext.js`)

Nickname + password; the login e-mail is `${normalizeNickname(nick)}@users.cappymeal-go.firebaseapp.com` (a subdomain of the Firebase-controlled domain, so nobody can receive password-reset mail for it). Registration goes only through the callable `registerAccount` (nickname `/^[a-z0-9áčďéěíňóřšťúůýž._-]{3,24}$/` after lowercasing, password 10–128, max 5 registrations per IP per hour, rejects a nickname that exists on either domain); the client then signs in. Legacy accounts use `@cappymeal.app` (an unregistered domain): `login` falls back to the legacy e-mail, calls `migrateLoginEmail` (server moves the account to the new domain and fixes the stored nickname) and signs in again; sessions still signed in with a legacy e-mail are migrated in the background on app start. Login stays case-insensitive. Also subscribes to `users/{uid}` (`{ nickname, householdId }`). `useAuth()` → `{ user, loading, profile, profileLoading, nickname, householdId, login, register, logout }`. `src/firebase.js` uses `initializeAuth` without a popup/redirect resolver (no auth iframe / apis.google.com – keeps the CSP tight).

### Household data (`src/context/HouseholdContext.js`)

Everything lives under `households/{hid}`: `name` (household display name, asked for on create, editable by the owner in Nastavení, fallback "Naše domácnost"), `owner` (uid of the creator; older households get it backfilled by `ensureHouseholdMeta` = member with the earliest `joinedAt`), `joinCode`, `members/{uid}: { nickname, joinedAt }` (max 6), `rohlik` (public Rohlík status `{ connected, emailMasked, connectedAt, by, method, needsReconnect? }`), `recipes/{rid}`, `plan/{YYYY-MM-DD}/{slot}: rid`, `orders/{date}: { status: 'in_cart'|'ordered', at, by, planChanged? }`, `pantry/{ingredientKey}: bool`, `regulars/{id}: { name, amount?, auto, createdBy, createdAt }` (regular shopping items), `productPrefs/{ingredientKey}: { productId, name, imageUrl?, priceText?, packText?, count, lastAt, by }` (remembered Rohlík product per item, written when the user confirms "Vložit do košíku"; regular items use their `regular:{id}` key), `settings` (incl. `settings/shop: { preferLight, preferBio, sort: 'best'|'unitPrice' }`, edited in Nastavení → "Nákup na Rohlíku"), `pushTokens/{uid}/{id}`, `activity`. Recipe photos live outside the household tree in `householdPhotos/{hid}/{rid}` (JPEG data URL < 400 000 chars, loaded lazily per recipe and cached by `rid:updatedAt`); `households/{hid}/photos/{rid}` is the read-only legacy location (read as fallback, moved to the new path on the recipe's next save). The context also exposes `owner`, `isOwner`, `rohlik`, `regulars`, `productPrefs` and `addRegular` / `updateRegular` / `deleteRegular` / `saveProductPrefs(chosen)`. One `onValue` subscription per sub-tree. `useHousehold()` exposes the data, `todayKey`, `horizon` (today + 13 days), `statusOf(date)`, `alert`, `pendingDays` and the actions `setMeal`, `removeMeal`, `saveRecipe(draft, photo)`, `deleteRecipe`, `togglePantry`, `setOrderStatus(days, status)`, `clearOrder`, `updateSettings`, `updateHouseholdName`, `logActivity`.
- Display names (nicknames, household name) always go through `capitalizeFirst` (`src/lib/text.js`). Login stays case-insensitive (`toEmail` lowercases); during the legacy-account migration (`migrateLoginEmail`) a missing / lowercase-email-derived profile nickname is rewritten server-side to the typed, capitalized form in `users/{uid}` and `households/{hid}/members/{uid}`.

- **Date keys are LOCAL dates** from `dateKey()` in `src/lib/dates.js` (never `toISOString()`). Past days are hidden, never deleted.
- Day status (`src/lib/meals.js` `dayStatus`): `ordered` / `in_cart` (from `orders`) / `pending` (has meals) / `empty`.
- Ingredient aggregation for the cart is keyed by `ingredientKey(name)` (trimmed, lowercased, RTDB-unsafe chars → `_`); staples regex pre-marks "Mám doma" unless `pantry` says otherwise.
- New households are seeded from `src/data/seedRecipes.js` (bundled images in `src/assets/recipes`, referenced by `builtinImage`).

### Rohlík flow (`src/screens/Cart.js`)

Each household connects its own Rohlík account (settings section "Účet Rohlík", `src/components/RohlikAccount.js`; only the owner can connect/disconnect). Pick days → aggregated list + selected regular items (`regulars` with `auto` are preselected; the per-shopping selection is local state; keys are prefixed `regular:` so they never merge with ingredient keys and are never auto-marked "Mám doma"; managed in `src/components/RegularsSheet.js`) → `matchProducts` → per item a variant carousel, "Přeskočit" toggle and quantity stepper → `fillCart` (the function marks days `in_cart`) → `/cart/done` → user confirms the order in the Rohlík app → "Objednávka je dokončená" sets `ordered`, which stops reminders. Not connected (or Rohlík rejects the stored login) → card linking to settings; functions failing → copy list to clipboard / mark as ordered manually. `src/services/rohlik.js` chunks requests to the server caps (60 items / 80 products).

Product selection ("best practice" picked by the owner):
- **Quantities** (`src/lib/quantity.js`): `sumNeed(amounts, name)` parses every amount into base units (g, ml, ks; kg/dkg/l/dl, `½`, `1,5`, `1-2` = upper bound, "lžíce" ≈ 15, "lžička" ≈ 5 – ml for liquids, "hrst" ≈ 30 g, "balení"/"plechovka"/… = whole packages, "špetka"/"dle chuti"/"dle potřeby" = no quantity) and sums them over the chosen days ("Potřeba: 450 g"); unknown or mixed units → no need, quantity defaults to 1 silently. g and ml are treated as 1:1. `packsFor(need, pack)` = ceil(need / pack) (1–50) + leftover ("zbude 90 g"); the carousel presets that quantity when a card is picked. No `\p{…}` / lookbehind in client regexes (old iOS Safari, Babel bloat).
- **Request**: each item is sent as `{ key, name, amounts, need?: {qty, unit g|ml|ks}, query? (user override from "Hledat jinak"), preferredProductId?, preferredName? }` plus `prefs` = `settings/shop`. "Hledat jinak" re-runs `rohlikMatch` for that one item with the typed query and without the remembered product (1 call, one search, counts toward the rate limit).
- **Server** (`functions/src/productSearch.js`, `matcher.js`, `quantity.js`): `planQuery` cleans the name (parentheses, "nebo"/"/" alternatives, amounts, preparation adjectives like "nastrouhaná", "uvařené", "na kostičky") and maps aliases through a small Czech dictionary to a canonical query ("bílky"/"žloutky"/"vajíčka" → "vejce", "cottage" → "cottage sýr", "kuřecí prsa" → "kuřecí prsní řízky", …) with per-ingredient negative keywords (+ generic baby/pet food exclusions, skipped when the query asks for them; if everything is excluded the unfiltered results are used). One search (limit 15), plus one extra search by `preferredName` when the remembered product is not among the results. `rank`: name-token match (diacritics-insensitive, word starts, light stemming) dominates, then the light/BIO boost from `prefs`, package fit vs. need, unit price; unavailable products last (dropped when ≥ 3 available); `sort: 'unitPrice'` orders relevant matches by Kč/kg|l|ks. Returns ≤ 5 candidates with `{ productId, name, price, priceText, unit, imageUrl, url, brand, packQty, packUnit, packText, unitPrice, unitPricePer, unitPriceText, available, badges[], preferred? }` and per item `preferred: null|'found'|'unavailable'|'missing'`. The adapter reads structured fields when present (unit price, package amount/unit, availability/stock, brand, category, badges/labels, BIO flag, original price → "Akce") and otherwise parses name/amount text. Verified Rohlík MCP facts (2026-11): search tool `batch_search_products` takes `{ queries: [{ keyword, filters? }] (max 4), context }` and returns JSON text `{ results: [{ query, products: [...] }] }` (≤ 5 products per query); product keys `productId, productName, textualAmount ("125 g"), price, brand, pricePerUnit{full,currency}, inStock, badges[] (bio, frozen, best-buy…), originalPrice, discountPercentage, xtraMemberPrice` – **no images**. Add tool `add_items_to_cart` takes `{ items: [{ productId (integer), quantity, actionId? }], context }` (`update_cart_item` must NOT be picked). Every tool wants a short `context` sentence (no personal data). Images + product URL come from Rohlík's public web API `https://www.rohlik.cz/api/v1/products?products=ID&products=ID…` (`images[]`, `slug`), fetched in batches after matching (`fetchProductImages`, best effort) and shown via `cdn.rohlik.cz/cdn-cgi/image/f=auto,w=320/…`. `rohlikMatch` logs the raw key set of the first result per request (`rohlikMatch raw product keys:`); `searchProducts` still supports an `onDiag` callback (tool/schema/response dump + one `get_product_details` probe) – not wired by default, pass it temporarily when debugging.
- **Remembered choice** (`src/lib/shop.js` `arrangeCandidates`): the remembered product goes first, preselected, badge "Vaše volba"; not found at all → its stored snapshot is shown first ("z minulého nákupu"); found but unavailable → the best available variant is preselected and the item says "Vaše volba není dostupná". On "Vložit do košíku" every non-skipped item's chosen variant is written to `productPrefs` (count + 1 when the same product again), best effort.
- **Carousel** (`src/components/ProductCarousel.js` + `productCarousel.css`): CSS scroll-snap (mandatory, center); phone: one card ≈ 70 % wide with neighbours peeking, swipe, dots; desktop: 3 cards, prev/next arrows. `role="listbox"` / `option` with `aria-selected`, roving tabindex, arrow keys / Home / End select, Enter/Space; unavailable cards are `aria-disabled`; respects `prefers-reduced-motion`. Tapping a card selects it (swiping only scrolls).

### Cloud Functions (`functions/`, europe-west1, CommonJS)

Callables (errors carry a generic Czech message + `details.code`; details only in logs, never request bodies or credentials): `registerAccount` (no auth), `migrateLoginEmail`, `createHousehold({ name, recipes })` (seeds the recipes sent by the client after validating them), `joinHousehold({ code })`, `ensureHouseholdMeta`, owner-only `rotateJoinCode` and `removeMember({ uid })` (also drops their push tokens, clears their `householdId`, rotates the code), owner-only `rohlikOAuthStart` / `rohlikOAuthFinish({ redirectUrl })` / `rohlikDisconnect`, member `rohlikStatus` (`{ connected, emailMasked, toolCount }`, tool names only for the owner), `rohlikMatch` (see product selection above; input validated in `validateMatchItems` / `validateShopPrefs`), `rohlikFillCart`. Scheduled `dailyReminders` (hourly; lists households via `householdIndex` + shallow REST, reads only `settings`, the next 3 days of `plan`/`orders` and `pushTokens` per household, each in its own try/catch). Rohlík OAuth tokens are encrypted with AES-256-GCM (`functions/src/crypto.js`, household id as AAD) under admin-only `rohlikCredentials/{hid}`; an MCP session is opened per request with that household's bearer token (tool list cached per session only). Rate limits (fixed 1 h window, `functions/src/rateLimit.js`) live in admin-only `rateLimits/`: `h/{hid}/{fn}` (rohlikMatch 30, rohlikFillCart 10, rohlikOAuthStart 10, rohlikOAuthFinish 10, rohlikStatus 60, rotateJoinCode 20), `u/{uid}/{fn}` (joinHousehold 10, createHousehold 5), `ip/{ip}/registerAccount` (5; cleared nightly). Input validators are in `functions/src/validate.js`. `maxInstances`: callables 3, scheduler 1.

### Security rules (`database.rules.json`, tests in `test/rules/`)

Default deny. `users/$uid`: self only, keys `nickname` (≤ 32) and `householdId` (only a household that already lists the user as a member). `joinCodes/$code`: single-key read for signed-in users, no client writes. `households/$hid`: read for members; the household root, `owner`, `joinCode`, `members` and `rohlik` are server-only (creating, joining, removing go through callables); the owner may write `name` (1–40); members may write validated `recipes`, `plan`, `orders` (`by` = self), `pantry`, `regulars`, `productPrefs` (strings ≤ 200, `imageUrl` https ≤ 500, `count` integer ≥ 1, `lastAt` number, `by` = self), `settings` (incl. `shop`), append-only `activity` (`by` = self) and their own `pushTokens/{uid}`. `householdPhotos/$hid`: members only, JPEG data URLs < 400 000 chars. `rohlikCredentials`, `rohlikOAuthClient`, `rohlikOAuthPending`, `rateLimits`, `householdIndex`: admin only. Every new client write path must satisfy these rules – add a case to `test/rules/database.rules.test.js`.

### Hosting

`firebase.json` sets security headers for all paths (CSP without inline scripts – the committed `.env` has `INLINE_RUNTIME_CHUNK=false`; X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy) plus no-cache for HTML and immutable caching for `/static/**`. A new external origin (fonts, APIs, images, scripts) must be added to the CSP. The hosting emulator does not apply `headers`. The messaging service worker only navigates to same-origin URLs.
