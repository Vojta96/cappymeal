# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm start                                   # Dev server on port 3000
npm run build                               # Production build (output: build/)
npm test                                    # Jest in watch mode
npm test -- --watchAll=false src/App.test.js  # Run a single test file once
node scripts/gen-icons.js                   # Regenerate PWA icons from src/Images/Cappy.png
npm test -- --watchAll=false -t "name"      # Run tests matching a name
npm run test:rules                          # RTDB rules tests (Database emulator, needs Java)
cd functions && npm test                    # Cloud Functions unit tests (node:test)
```

There is no separate lint script; ESLint (`react-app` config) runs inside `npm start` / `npm run build`.

Tests never touch real Firebase: `src/App.test.js` covers the pure helpers in `src/lib/`, `src/screens/screens.test.js` smoke-renders every screen with a fake `HouseholdContext` value and mocked `firebase`/`services`. CRA sets `resetMocks`, so mock factories use plain functions, not `jest.fn`. `CI=true npm run build` treats ESLint warnings as errors.

Deploy (only on the owner's explicit request), always in this order: `firebase deploy --only functions`, then `firebase deploy --only database`, then `npm run build && firebase deploy --only hosting` (new clients need the callables; the rules block the old client-side writes). The only secret is `ROHLIK_ENC_KEY` (`firebase functions:secrets:set ROHLIK_ENC_KEY`, value = base64 of 32 random bytes; changing it makes every stored Rohlík login unreadable, households then have to reconnect). For the emulators put it in `functions/.secret.local` (never commit it).

## Stack

- **React 18** (JavaScript, not TypeScript) via Create React App; **React Router v6** (`BrowserRouter` in `src/index.js`)
- Plain CSS, no UI library: design tokens in `src/styles/tokens.css`, shared components in `src/styles/ui.css`, one CSS file per screen. Fonts Manrope + Instrument Serif and Material Symbols Rounded icons are loaded from Google Fonts in `public/index.html` (`<Icon name="..."/>` in `src/components/ui.js`).
- **Firebase** (project `cappymeal-go`): Auth, Realtime Database (europe-west1), Cloud Functions (europe-west1, Rohlík + reminders, in `functions/`), Messaging, Hosting. `src/firebase.js` exports `app`, `db`, `auth`, `functions`; callables go through `callFunction` in `src/services/functions.js`.
- Mobile-first PWA: `public/manifest.json`, icons generated by `scripts/gen-icons.js`, iOS safe areas via `env(safe-area-inset-*)`.
- Responsive: < 521px phone; 521–1023px the phone layout in a centered 480px column; **>= 1024px desktop** – left sidebar (`Sidebar` in `AppLayout.js`) instead of the tab bar, wide multi-column screens, bottom sheets shown as centered modals, push banner as a top-right toast, split login/onboarding (`AuthLayout`). Mostly CSS (`@media (min-width: 1024px)` blocks at the end of each CSS file, `.only-mobile` / `.only-desktop` helpers, `display: contents` wrappers); `useIsDesktop()` from `src/hooks/useMediaQuery.js` is used only where the component tree differs (AppLayout, Home, Plan week grid, RecipeDetail, Cart side panel). Changes to the phone layout must keep both variants working.

UI text and recipe data are in Czech.

## Architecture

The shared data model (RTDB layout, day statuses, Cloud Function APIs) is documented in the redesign contract; the essentials are below.

- `src/screens/` – one component per route; `src/components/` – AppLayout (tab bar, banner), BottomSheet, Thumb (recipe photo/emoji), PushBanner; `src/context/` – Auth and Household; `src/lib/` – pure logic (dates, meals, join codes, image resize); `src/services/` – Firebase-touching helpers (`household.js` onboarding; `rohlik.js` and `push.js` are client wrappers for the Cloud Functions / FCM).

### Routing and gating (`src/App.js`)

`AuthProvider > Gate`. Logged out → only `/login`. Logged in but `users/{uid}.householdId` empty → only `/household` (create a household or join with an 8-char code). Otherwise `HouseholdProvider > BannerProvider > AppLayout` with `/`, `/plan`, `/recipes`, `/recipes/new`, `/recipes/:id`, `/recipes/:id/edit`, `/cart`, `/cart/done`, `/notifications`. The tab bar is hidden on `/recipes/:id*`.

### Auth (`src/context/AuthContext.js`)

Nickname + password; the login e-mail is `${normalizeNickname(nick)}@users.cappymeal-go.firebaseapp.com` (a subdomain of the Firebase-controlled domain, so nobody can receive password-reset mail for it). Registration goes only through the callable `registerAccount` (nickname `/^[a-z0-9áčďéěíňóřšťúůýž._-]{3,24}$/` after lowercasing, password 10–128, max 5 registrations per IP per hour, rejects a nickname that exists on either domain); the client then signs in. Legacy accounts use `@cappymeal.app` (an unregistered domain): `login` falls back to the legacy e-mail, calls `migrateLoginEmail` (server moves the account to the new domain and fixes the stored nickname) and signs in again; sessions still signed in with a legacy e-mail are migrated in the background on app start. Login stays case-insensitive. Also subscribes to `users/{uid}` (`{ nickname, householdId }`). `useAuth()` → `{ user, loading, profile, profileLoading, nickname, householdId, login, register, logout }`. `src/firebase.js` uses `initializeAuth` without a popup/redirect resolver (no auth iframe / apis.google.com – keeps the CSP tight).

### Household data (`src/context/HouseholdContext.js`)

Everything lives under `households/{hid}`: `name` (household display name, asked for on create, editable by the owner in Upozornění, fallback "Naše domácnost"), `owner` (uid of the creator; older households get it backfilled by `ensureHouseholdMeta` = member with the earliest `joinedAt`), `joinCode`, `members/{uid}: { nickname, joinedAt }` (max 6), `rohlik` (public Rohlík status `{ connected, emailMasked, connectedAt, by }`), `recipes/{rid}`, `plan/{YYYY-MM-DD}/{slot}: rid`, `orders/{date}: { status: 'in_cart'|'ordered', at, by, planChanged? }`, `pantry/{ingredientKey}: bool`, `regulars/{id}: { name, amount?, auto, createdBy, createdAt }` (regular shopping items), `settings`, `pushTokens/{uid}/{id}`, `activity`. Recipe photos live outside the household tree in `householdPhotos/{hid}/{rid}` (JPEG data URL < 400 000 chars, loaded lazily per recipe and cached by `rid:updatedAt`); `households/{hid}/photos/{rid}` is the read-only legacy location (read as fallback, moved to the new path on the recipe's next save). The context also exposes `owner`, `isOwner`, `rohlik`, `regulars` and `addRegular` / `updateRegular` / `deleteRegular`. One `onValue` subscription per sub-tree. `useHousehold()` exposes the data, `todayKey`, `horizon` (today + 13 days), `statusOf(date)`, `alert`, `pendingDays` and the actions `setMeal`, `removeMeal`, `saveRecipe(draft, photo)`, `deleteRecipe`, `togglePantry`, `setOrderStatus(days, status)`, `clearOrder`, `updateSettings`, `updateHouseholdName`, `logActivity`.
- Display names (nicknames, household name) always go through `capitalizeFirst` (`src/lib/text.js`). Login stays case-insensitive (`toEmail` lowercases); during the legacy-account migration (`migrateLoginEmail`) a missing / lowercase-email-derived profile nickname is rewritten server-side to the typed, capitalized form in `users/{uid}` and `households/{hid}/members/{uid}`.

- **Date keys are LOCAL dates** from `dateKey()` in `src/lib/dates.js` (never `toISOString()`). Past days are hidden, never deleted.
- Day status (`src/lib/meals.js` `dayStatus`): `ordered` / `in_cart` (from `orders`) / `pending` (has meals) / `empty`.
- Ingredient aggregation for the cart is keyed by `ingredientKey(name)` (trimmed, lowercased, RTDB-unsafe chars → `_`); staples regex pre-marks "Mám doma" unless `pantry` says otherwise.
- New households are seeded from `src/data/seedRecipes.js` (bundled images in `src/assets/recipes`, referenced by `builtinImage`).

### Rohlík flow (`src/screens/Cart.js`)

Each household connects its own Rohlík account (settings section "Účet Rohlík", `src/components/RohlikAccount.js`; only the owner can connect/disconnect). Pick days → aggregated list + selected regular items (`regulars` with `auto` are preselected; the per-shopping selection is local state; keys are prefixed `regular:` so they never merge with ingredient keys and are never auto-marked "Mám doma"; managed in `src/components/RegularsSheet.js`) → `matchProducts` (up to 5 deduplicated variants per item) → pick a variant card or "Přeskočit" and a quantity (1–50) per item → `fillCart` (the function marks days `in_cart`) → `/cart/done` → user confirms the order in the Rohlík app → "Objednávka je dokončená" sets `ordered`, which stops reminders. Not connected (or Rohlík rejects the stored login) → card linking to settings; functions failing → copy list to clipboard / mark as ordered manually. `src/services/rohlik.js` chunks requests to the server caps (60 items / 80 products).

### Cloud Functions (`functions/`, europe-west1, CommonJS)

Callables (errors carry a generic Czech message + `details.code`; details only in logs, never request bodies or credentials): `registerAccount` (no auth), `migrateLoginEmail`, `createHousehold({ name, recipes })` (seeds the recipes sent by the client after validating them), `joinHousehold({ code })`, `ensureHouseholdMeta`, owner-only `rotateJoinCode` and `removeMember({ uid })` (also drops their push tokens, clears their `householdId`, rotates the code), owner-only `rohlikConnect({ email, password })` / `rohlikDisconnect`, member `rohlikStatus` (`{ connected, emailMasked, toolCount }`, tool names only for the owner), `rohlikMatch`, `rohlikFillCart`. Scheduled `dailyReminders` (hourly; lists households via `householdIndex` + shallow REST, reads only `settings`, the next 3 days of `plan`/`orders` and `pushTokens` per household, each in its own try/catch). Rohlík credentials are encrypted with AES-256-GCM (`functions/src/crypto.js`, household id as AAD) under admin-only `rohlikCredentials/{hid}`; an MCP session is opened per request with that household's credentials (tool list cached per session only). Rate limits (fixed 1 h window, `functions/src/rateLimit.js`) live in admin-only `rateLimits/`: `h/{hid}/{fn}` (rohlikMatch 30, rohlikFillCart 10, rohlikConnect 5, rohlikStatus 60, rotateJoinCode 20), `u/{uid}/{fn}` (joinHousehold 10, createHousehold 5), `ip/{ip}/registerAccount` (5; cleared nightly). Input validators are in `functions/src/validate.js`. `maxInstances`: callables 3, scheduler 1.

### Security rules (`database.rules.json`, tests in `test/rules/`)

Default deny. `users/$uid`: self only, keys `nickname` (≤ 32) and `householdId` (only a household that already lists the user as a member). `joinCodes/$code`: single-key read for signed-in users, no client writes. `households/$hid`: read for members; the household root, `owner`, `joinCode`, `members` and `rohlik` are server-only (creating, joining, removing go through callables); the owner may write `name` (1–40); members may write validated `recipes`, `plan`, `orders` (`by` = self), `pantry`, `regulars`, `settings`, append-only `activity` (`by` = self) and their own `pushTokens/{uid}`. `householdPhotos/$hid`: members only, JPEG data URLs < 400 000 chars. `rohlikCredentials`, `rateLimits`, `householdIndex`: admin only. Every new client write path must satisfy these rules – add a case to `test/rules/database.rules.test.js`.

### Hosting

`firebase.json` sets security headers for all paths (CSP without inline scripts – the committed `.env` has `INLINE_RUNTIME_CHUNK=false`; X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy) plus no-cache for HTML and immutable caching for `/static/**`. A new external origin (fonts, APIs, images, scripts) must be added to the CSP. The hosting emulator does not apply `headers`. The messaging service worker only navigates to same-origin URLs.
