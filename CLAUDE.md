# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm start                                   # Dev server on port 3000
npm run build                               # Production build (output: build/)
npm test                                    # Jest in watch mode
npm test -- --watchAll=false src/App.test.js  # Run a single test file once
node scripts/gen-icons.js                   # Regenerate PWA icons from src/Images/Cappy.png
npm test -- --watchAll=false -t "name"      # Run tests matching a name
npm run test:rules                          # RTDB rules tests (Database emulator, needs Java)
cd functions && npm test                    # Cloud Functions unit tests (node:test)
```

There is no separate lint script; ESLint (`react-app` config) runs inside `npm start` / `npm run build`.

Tests never touch real Firebase: `src/App.test.js` covers the pure helpers in `src/lib/` (`src/lib/quantity.test.js` covers amounts / packages and the product-selection helpers in `src/lib/shop.js`), `src/screens/screens.test.js` smoke-renders every screen with a fake `HouseholdContext` value and mocked `firebase`/`services`. CRA sets `resetMocks`, so mock factories use plain functions, not `jest.fn`. `CI=true npm run build` treats ESLint warnings as errors.

Deploy (only on the owner's explicit request), always in this order: `firebase deploy --only functions`, then `firebase deploy --only database`, then `npm run build && firebase deploy --only hosting` (new clients need the callables; the rules block the old client-side writes). The only secret is `ROHLIK_ENC_KEY` (`firebase functions:secrets:set ROHLIK_ENC_KEY`, value = base64 of 32 random bytes; changing it makes every stored Rohlík token unreadable, households then have to reconnect). For the emulators put it in `functions/.secret.local` (never commit it).

## Stack

- **React 18** (JavaScript, not TypeScript) via Create React App; **React Router v6** (`BrowserRouter` in `src/index.js`)
- Plain CSS, no UI library: design tokens in `src/styles/tokens.css`, shared components in `src/styles/ui.css`, one CSS file per screen. Fonts Manrope + Instrument Serif and Material Symbols Rounded icons are loaded from Google Fonts in `public/index.html` (`<Icon name="..."/>` in `src/components/ui.js`).
- **Firebase** (project `cappymeal-go`): Auth, Realtime Database (europe-west1), Cloud Functions (europe-west1, Rohlík + reminders, in `functions/`), Messaging, Hosting. `src/firebase.js` exports `app`, `db`, `auth`, `functions`; callables go through `callFunction` in `src/services/functions.js`.
- Mobile-first PWA: `public/manifest.json`, icons generated by `scripts/gen-icons.js`, iOS safe areas via `env(safe-area-inset-*)`.
- Responsive: < 521px phone; 521–1023px the phone layout in a centered 480px column; **>= 1024px desktop** – left sidebar (`Sidebar` in `AppLayout.js`) instead of the tab bar, wide multi-column screens, bottom sheets shown as centered modals, push banner as a top-right toast, split login/onboarding (`AuthLayout`). Mostly CSS (`@media (min-width: 1024px)` blocks at the end of each CSS file, `.only-mobile` / `.only-desktop` helpers, `display: contents` wrappers); `useIsDesktop()` from `src/hooks/useMediaQuery.js` is used only where the component tree differs (AppLayout, Home, Plan week grid, RecipeDetail, Cart side panel). Changes to the phone layout must keep both variants working.

UI text and recipe data are in Czech.

## Architecture

The shared data model (RTDB layout, day statuses, Cloud Function APIs) is documented in the redesign contract; the essentials are below.

- `src/screens/` – one component per route; `src/components/` – AppLayout (tab bar, banner), BottomSheet, Thumb (recipe photo/emoji), PushBanner; `src/context/` – Auth and Household; `src/lib/` – pure logic (dates, meals, join codes, image resize); `src/services/` – Firebase-touching helpers (`household.js` onboarding; `rohlik.js` and `push.js` are client wrappers for the Cloud Functions / FCM).

### Routing and gating (`src/App.js`)

`AuthProvider > Gate`. Logged out → only `/login`. Logged in but `users/{uid}.householdId` empty → only `/household` (create a household or join with an 8-char code). Otherwise `HouseholdProvider > BannerProvider > AppLayout` with `/`, `/plan`, `/recipes`, `/recipes/new`, `/recipes/:id`, `/recipes/:id/edit`, `/cart`, `/cart/checkout` (`/cart/done` = old links, same screen), `/notifications`, `/settings`. The tab bar is hidden on `/recipes/:id*`. `/notifications` (Upozornění) is only the notifications list; `/settings` (Nastavení, `src/screens/Settings.js`) holds the cards Domácnost (name for the owner, join code + share + new code, members with remove for the owner), Účet Rohlík, Nákup na Rohlíku, Doručení z Rohlíku (only when connected, `src/components/DeliverySettings.js`), Připomínky (toggles, hour, push enable + iPhone hint) and Účet (logout). Entry points: the household block at the bottom of the desktop sidebar (a link to `/settings`, logout lives only in Settings), the gear button in the Přehled header and on Upozornění (mobile), and a card on Upozornění.

### Auth (`src/context/AuthContext.js`)

Nickname + password; the login e-mail is `${normalizeNickname(nick)}@users.cappymeal-go.firebaseapp.com` (a subdomain of the Firebase-controlled domain, so nobody can receive password-reset mail for it). Registration goes only through the callable `registerAccount` (nickname `/^[a-z0-9áčďéěíňóřšťúůýž._-]{3,24}$/` after lowercasing, password 10–128, max 5 registrations per IP per hour, rejects a nickname that exists on either domain); the client then signs in. Legacy accounts use `@cappymeal.app` (an unregistered domain): `login` falls back to the legacy e-mail, calls `migrateLoginEmail` (server moves the account to the new domain and fixes the stored nickname) and signs in again; sessions still signed in with a legacy e-mail are migrated in the background on app start. Login stays case-insensitive. Also subscribes to `users/{uid}` (`{ nickname, householdId }`). `useAuth()` → `{ user, loading, profile, profileLoading, nickname, householdId, login, register, logout }`. `src/firebase.js` uses `initializeAuth` without a popup/redirect resolver (no auth iframe / apis.google.com – keeps the CSP tight).

### Household data (`src/context/HouseholdContext.js`)

Everything lives under `households/{hid}`: `name` (household display name, asked for on create, editable by the owner in Nastavení, fallback "Naše domácnost"), `owner` (uid of the creator; older households get it backfilled by `ensureHouseholdMeta` = member with the earliest `joinedAt`), `joinCode`, `members/{uid}: { nickname, joinedAt }` (max 6), `rohlik` (public Rohlík status `{ connected, emailMasked, connectedAt, by, method, needsReconnect? }`), `recipes/{rid}`, `plan/{YYYY-MM-DD}/{slot}: rid`, `orders/{date}: { status: 'in_cart'|'ordered', at, by, planChanged?, rohlikOrderId? }` (`rohlikOrderId` written by `rohlikSyncOrders`), `pantry/{ingredientKey}: bool`, `regulars/{id}: { name, amount?, auto, createdBy, createdAt }` (regular shopping items), `productPrefs/{ingredientKey}: { productId, name, imageUrl?, priceText?, packText?, count, lastAt, by }` (remembered Rohlík product per item, written when the user confirms "Vložit do košíku"; regular items use their `regular:{id}` key), `settings` (incl. `settings/shop: { preferLight, preferBio, sort: 'best'|'unitPrice' }`, edited in Nastavení → "Nákup na Rohlíku"; `settings/delivery: { addressId?, addressLabel?, window: 'morning'|'afternoon'|'evening'|'any', lead: 'dayBefore'|'sameDay', paymentId?, paymentLabel?, courierNote? (≤ 300, applied ≤ 230), packaging?: 'PAPER_BAGS'|'REUSABLE_BAGS' }`, edited in Nastavení → "Doručení z Rohlíku", read via `deliveryPrefs()` in `src/lib/checkout.js`), `pushTokens/{uid}/{id}`, `activity`. Recipe photos live outside the household tree in two paths: `householdPhotos/{hid}/{rid}` (full photo, ~1000 px JPEG data URL < 400 000 chars; only the recipe detail hero and the editor preview load it, memory-only LRU of 60, never persisted) and `householdThumbs/{hid}/{rid}` (thumbnail, longer side 320 px, JPEG ~q0.7, data URL < 40 000 chars, rules limit 45 000; used by every list / small context: Home, Plan incl. the desktop grid, meal pickers, recipe cards). `saveRecipe` writes both in one multi-path update (thumb made by `makeThumb` in `src/lib/image.js`); `deleteRecipe` / `replaceRecipesWithSeed` remove both. `Thumb` takes `variant` (`thumb` default | `full`) and is lazy by default (IntersectionObserver, rootMargin 300 px; `lazy={false}` only for critical above-the-fold images); `requestPhoto(rid, variant)` / `photoFor(rid, variant)` in the context. Thumbs are cached on the device in IndexedDB (`src/lib/photoCache.js`, db `cappymeal`, store `thumbs`, key `{hid}:{rid}:{updatedAt}`, pruned once per session; every call is best effort and silently falls back to the network when IndexedDB is unavailable). Lookup order for a thumb: memory, IndexedDB, RTDB; if the thumb is missing (photo saved before thumbs existed), the full photo is loaded once, the thumb is generated in the browser and written to RTDB (also done when a full photo is loaded and no thumb exists; once per session per rid). `households/{hid}/photos/{rid}` is the read-only legacy location (read as fallback, moved to the new path on the recipe's next save). The context also exposes `owner`, `isOwner`, `rohlik`, `regulars`, `productPrefs` and `addRegular` / `updateRegular` / `deleteRegular` / `saveProductPrefs(chosen)`. One `onValue` subscription per sub-tree. `useHousehold()` exposes the data, `todayKey`, `horizon` (today + 13 days), `statusOf(date)`, `alert`, `pendingDays` and the actions `setMeal`, `removeMeal`, `saveRecipe(draft, photo)`, `deleteRecipe`, `togglePantry`, `setOrderStatus(days, status)`, `clearOrder`, `updateSettings`, `updateHouseholdName`, `logActivity`.
- Display names (nicknames, household name) always go through `capitalizeFirst` (`src/lib/text.js`). Login stays case-insensitive (`toEmail` lowercases); during the legacy-account migration (`migrateLoginEmail`) a missing / lowercase-email-derived profile nickname is rewritten server-side to the typed, capitalized form in `users/{uid}` and `households/{hid}/members/{uid}`.

- **Date keys are LOCAL dates** from `dateKey()` in `src/lib/dates.js` (never `toISOString()`). Past days are hidden, never deleted.
- Day status (`src/lib/meals.js` `dayStatus`): `ordered` / `in_cart` (from `orders`) / `pending` (has meals) / `empty`.
- Ingredient aggregation for the cart is keyed by `ingredientKey(name)` (trimmed, lowercased, RTDB-unsafe chars → `_`); staples regex pre-marks "Mám doma" unless `pantry` says otherwise.
- New households are seeded from `src/data/seedRecipes.js` (bundled images in `src/assets/recipes`, referenced by `builtinImage`).

### Rohlík flow (`src/screens/Cart.js`)

Each household connects its own Rohlík account (settings section "Účet Rohlík", `src/components/RohlikAccount.js`; only the owner can connect/disconnect). Pick days → aggregated list + selected regular items (`regulars` with `auto` are preselected; the per-shopping selection is local state; keys are prefixed `regular:` so they never merge with ingredient keys and are never auto-marked "Mám doma"; managed in `src/components/RegularsSheet.js`) → `matchProducts` → per item a variant carousel, "Přeskočit" toggle and quantity stepper → `fillCart` (the function marks days `in_cart`; the added product ids go to sessionStorage `cappymeal-cart-added`) → `/cart/checkout` (see Checkout below). Not connected (or Rohlík rejects the stored login) → card linking to settings; functions failing → copy list to clipboard / mark as ordered manually. `src/services/rohlik.js` chunks requests to the server caps (60 items / 80 products).

Product selection ("best practice" picked by the owner):
- **Quantities** (`src/lib/quantity.js`): `sumNeed(amounts, name)` parses every amount into base units (g, ml, ks; kg/dkg/l/dl, `½`, `1,5`, `1-2` = upper bound, "lžíce" ≈ 15, "lžička" ≈ 5 – ml for liquids, "hrst" ≈ 30 g, "balení"/"plechovka"/… = whole packages, "špetka"/"dle chuti"/"dle potřeby" = no quantity) and sums them over the chosen days ("Potřeba: 450 g"); unknown or mixed units → no need, quantity defaults to 1 silently. g and ml are treated as 1:1. `packsFor(need, pack)` = ceil(need / pack) (1–50) + leftover ("zbude 90 g"); the carousel presets that quantity when a card is picked. No `\p{…}` / lookbehind in client regexes (old iOS Safari, Babel bloat).
- **Request**: each item is sent as `{ key, name, amounts, need?: {qty, unit g|ml|ks}, query? (user override from "Hledat jinak"), preferredProductId?, preferredName? }` plus `prefs` = `settings/shop`. "Hledat jinak" re-runs `rohlikMatch` for that one item with the typed query and without the remembered product (1 call, one search, counts toward the rate limit).
- **Server** (`functions/src/productSearch.js`, `matcher.js`, `quantity.js`): `planQuery` cleans the name (parentheses, "nebo"/"/" alternatives, amounts, preparation adjectives like "nastrouhaná", "uvařené", "na kostičky") and maps aliases through a small Czech dictionary to a canonical query ("bílky"/"žloutky"/"vajíčka" → "vejce", "cottage" → "cottage sýr", "kuřecí prsa" → "kuřecí prsní řízky", …) with per-ingredient negative keywords (+ generic baby/pet food exclusions, skipped when the query asks for them; if everything is excluded the unfiltered results are used). One search (limit 15), plus one extra search by `preferredName` when the remembered product is not among the results. `rank`: name-token match (diacritics-insensitive, word starts, light stemming) dominates, then the light/BIO boost from `prefs`, package fit vs. need, unit price; unavailable products last (dropped when ≥ 3 available); `sort: 'unitPrice'` orders relevant matches by Kč/kg|l|ks. Returns ≤ 5 candidates with `{ productId, name, price, priceText, unit, imageUrl, url, brand, packQty, packUnit, packText, unitPrice, unitPricePer, unitPriceText, available, badges[], preferred? }` and per item `preferred: null|'found'|'unavailable'|'missing'`. The adapter reads structured fields when present (unit price, package amount/unit, availability/stock, brand, category, badges/labels, BIO flag, original price → "Akce") and otherwise parses name/amount text. Verified Rohlík MCP facts (2026-11): search tool `batch_search_products` takes `{ queries: [{ keyword, filters? }] (max 4), context }` and returns JSON text `{ results: [{ query, products: [...] }] }` (≤ 5 products per query); product keys `productId, productName, textualAmount ("125 g"), price, brand, pricePerUnit{full,currency}, inStock, badges[] (bio, frozen, best-buy…), originalPrice, discountPercentage, xtraMemberPrice` – **no images**. Add tool `add_items_to_cart` takes `{ items: [{ productId (integer), quantity, actionId? }], context }` (`update_cart_item` must NOT be picked). Every tool wants a short `context` sentence (no personal data). Images + product URL come from Rohlík's public web API `https://www.rohlik.cz/api/v1/products?products=ID&products=ID…` (`images[]`, `slug`), fetched in batches after matching (`fetchProductImages`, best effort) and shown via `cdn.rohlik.cz/cdn-cgi/image/f=auto,w=320/…`. `rohlikMatch` logs the raw key set of the first result per request (`rohlikMatch raw product keys:`); `searchProducts` still supports an `onDiag` callback (tool/schema/response dump) – not wired by default, pass it temporarily when debugging. The temporary checkout inspection (`inspectCheckoutTools` in `rohlikStatus`) is removed.
- **Remembered choice** (`src/lib/shop.js` `arrangeCandidates`): the remembered product goes first, preselected, badge "Vaše volba"; not found at all → its stored snapshot is shown first ("z minulého nákupu"); found but unavailable → the best available variant is preselected and the item says "Vaše volba není dostupná". On "Vložit do košíku" every non-skipped item's chosen variant is written to `productPrefs` (count + 1 when the same product again), best effort.
- **Carousel** (`src/components/ProductCarousel.js` + `productCarousel.css`): CSS scroll-snap (mandatory, center); phone: one card ≈ 70 % wide with neighbours peeking, swipe, dots; desktop: 3 cards, prev/next arrows. `role="listbox"` / `option` with `aria-selected`, roving tabindex, arrow keys / Home / End select, Enter/Space; unavailable cards are `aria-disabled`; respects `prefers-reduced-motion`. Tapping a card selects it (swiping only scrolls).

### Checkout (`src/screens/CartCheckout.js` + `checkout.css`, server `functions/src/checkout.js`)

Rohlík MCP has no tool to submit an order and Rohlík's terms require the customer to confirm it in Rohlík, so everything up to that point happens in CappyMeal and the last step opens Rohlík's checkout link. Cards (phone stacked + sticky button, desktop ≥ 1024px two columns with a sticky summary): 1 **Košík na Rohlíku** (`rohlikCart`: everything in the Rohlík cart, items not added by this shopping are marked "už v košíku"; stepper → `updateCartItem` debounced 700 ms, 1 → bin → `removeCartItem`), 2 **Doručení** (address options when > 1, day tabs Dnes/Zítra/+2/+3 → `rohlikTimeslots`, slot chips with price; the first available slot inside `settings/delivery/window` gets a "Doporučeno" badge but is never selected automatically; the day tab opens on the earliest shopping day, minus one with `lead: 'dayBefore'`, clamped 0–3), 3 **Platba** (methods from the checkout; only `CARD_ON_PLACE` / `CASH` can be set in CappyMeal, online card etc. "zvolíte na Rohlíku"; printed receipt toggle when offered), 4 **Pro kurýra** (note ≤ 230, call-on-arrival toggle, packaging), 5 **Souhrn** (Rohlík's `price_breakdown` lines, estimated total, card-hold note, validation warnings, minimum order from the cart). On load `rohlikCheckout({ applyDefaults: true })` applies `settings/delivery` (address, payment, packaging, courier note – only when set, settable and different; best effort, one session). "Potvrdit a zaplatit na Rohlíku" opens the prefetched `rohlikCheckoutLink` URL (https on `rohlik.cz` only, validated server-side) in a new tab; then the screen waits and `rohlikSyncOrders` runs on focus / visibilitychange (min 15 s gap) and on "Zkontrolovat objednávku" → "Objednávka přijata ✓". Fallback links "Objednávku jsem dokončil(a)" (manual `ordered`) and "Košík jsem zrušil" (days back to pending). Not connected → the old manual card.

**Sync logic** (`decideSync`): only when the household has `in_cart` days from today on (else `{ result: 'idle' }`, Rohlík is not called). Calls `fetch_orders({ limit: 5, order_type: 'both' })` + `get_cart`. An order (not cancelled) with `orderTime ≥ earliest in_cart at − 60 s` → those days `{ status: 'ordered', at, by, rohlikOrderId }` + activity entry (reminders stop). Otherwise an empty cart (both calls succeeded, newest fill older than 2 min) → `orders/{day}` removed (back to pending). Days are re-read before writing (only still-in_cart days with the same `at`). The client calls `syncRohlikOrders()` (throttled to once per 2 min per app session) on Přehled and Nákup when some day is `in_cart` and Rohlík is connected, and forced on the checkout screen.

**Verified tool shapes** (JSON in `content[0].text`): `get_cart` → `{ status, data: { totalPrice, totalSavings, minimalStandardOrderPrice, submitConditionPassed, items: { [id]: { productId, productName, quantity, price, textualAmount, imgPath, maxBasketAmount, originalPrice?, … } }, categories, companies } }` (whether item `price` is per line or per unit is decided at runtime by comparing sums with `totalPrice`); `get_checkout` → `{ sections: { addressSection{ delivery_address, addressId, available_delivery_types, selected_delivery_type, is_valid }, contactSection (personal – never returned), courierSection{ delivery_note, call_on_arrival }, packagingSection{ selected_packaging }, paymentSection{ selected_method, available_methods[string], do_not_print_delivery_note, show_do_not_print_delivery_note }, timeslotSection{ slot_id, delivery_type, delivery_time, is_valid } }, validation_warnings[], order_details{ estimated_total, card_hold_total, price_breakdown[string], price_note }, checkout_ready, suborder? }`; `get_user_addresses` → `{ addresses: [{ id, fullAddress, isDeliveredTo }] }` (returned as id + short label without postal code); `fetch_orders` → `{ orders: [{ id, orderTime, state, deliverySlot{ timeRange }, priceComposition{ total{ amount } }, items, address, … }] }` (only id/time/state/slot/total are used); `get_checkout_link` → `{ checkout_link }`. **`get_timeslots_checkout` output is NOT verified yet**: `parseTimeslots` searches defensively (slotId/slot_id, since/till/start/end/timeWindow, price, capacityPercent 'NO CAPACITY', reservationEnabled, type) and `rohlikTimeslots` logs the masked shape once per instance (`rohlikTimeslots shape:`) – tune the parser from that log. Argument mapping: `get_timeslots_checkout { timeslots_day: '0'..'3', include_15min_slots: false }`, `select_delivery_address_checkout { address_id: int }`, `change_timeslot_checkout { timeslot_id: string }` (+ best-effort `reserve_timeslot { timeslot_id: int, slot_type: ON_TIME|VIRTUAL }` only for listing entries with `reservationEnabled`), `update_payment_method_checkout { selected_payment_method: CARD_ON_PLACE|CASH }`, `change_checkout_packaging { selected_packaging: PAPER_BAGS|REUSABLE_BAGS }`, `update_courier_instructions_checkout { note ≤ 230, call_on_arrival? }`, `toggle_delivery_note_checkout { do_not_print_delivery_note }`, `update_cart_item { product_id: int, quantity 0–50 }`, `remove_cart_item { product_id: int }`.

**Allowlist** (`ALLOWED_TOOLS` / `callAllowed` in `functions/src/rohlikAdapter.js`, every MCP call goes through it; `callJson` parses the payload and throws `ToolError` with a masked summary on `isError`): `batch_search_products, add_items_to_cart, get_cart, update_cart_item, remove_cart_item, get_checkout, get_user_addresses, select_delivery_address_checkout, get_timeslots_checkout, change_timeslot_checkout, reserve_timeslot, unreserve_timeslot, update_payment_method_checkout, change_checkout_packaging, toggle_delivery_note_checkout, update_courier_instructions_checkout, get_checkout_link, fetch_orders`. Never `clear_cart` (the cart may hold other things), order cancel/repeat/edit, claims, credits, shopping lists, scheduled tasks, `set_checkout_as_suborder`. Tool error texts are never logged (only pydantic validation errors with input values masked, else `text(length)`).

**Delivery prefs and reminders**: `lead: 'dayBefore'` moves the deadline one day earlier – `buildAlert(…, shift)` covers tomorrow..+4 and `computeReminderDates` reminds on D-4 (`remind3d`) and D-3..D-1 (`remindDaily`); `sameDay` (default) keeps D-3 / D-2, D-1.

### Cloud Functions (`functions/`, europe-west1, CommonJS)

Callables (errors carry a generic Czech message + `details.code`; details only in logs, never request bodies or credentials): `registerAccount` (no auth), `migrateLoginEmail`, `createHousehold({ name, recipes })` (seeds the recipes sent by the client after validating them), `joinHousehold({ code })`, `ensureHouseholdMeta`, owner-only `rotateJoinCode` and `removeMember({ uid })` (also drops their push tokens, clears their `householdId`, rotates the code), owner-only `rohlikOAuthStart` / `rohlikOAuthFinish({ redirectUrl })` / `rohlikDisconnect`, member `rohlikStatus` (`{ connected, emailMasked, toolCount }`, tool names only for the owner), `rohlikMatch` (see product selection above; input validated in `validateMatchItems` / `validateShopPrefs`), `rohlikFillCart`, and the checkout callables (any member, household's connected account): `rohlikCart`, `rohlikCheckout({ applyDefaults?, skip? })`, `rohlikTimeslots({ day: 0–3 })`, `rohlikCheckoutUpdate({ action, … })` (selectAddress / selectSlot / setPayment / setPackaging / setCourierNote / toggleDeliveryNote / updateCartItem / removeCartItem; returns the fresh checkout, + cart for cart actions), `rohlikCheckoutLink`, `rohlikDeliveryOptions` (Settings: addresses + payment methods), `rohlikSyncOrders` (validators `validateDayIndex` / `validateCheckoutLoad` / `validateCheckoutUpdate`; a Rohlík `isError` → `ROHLIK_REJECTED`, a 401/403 during a call → household marked for reconnect). Scheduled `dailyReminders` (hourly; lists households via `householdIndex` + shallow REST, reads only `settings`, the next 3 days (4 with `lead: 'dayBefore'`) of `plan`/`orders` and `pushTokens` per household, each in its own try/catch). Rohlík OAuth tokens are encrypted with AES-256-GCM (`functions/src/crypto.js`, household id as AAD) under admin-only `rohlikCredentials/{hid}`; an MCP session is opened per request with that household's bearer token (tool list cached per session only). Rate limits (fixed 1 h window, `functions/src/rateLimit.js`) live in admin-only `rateLimits/`: `h/{hid}/{fn}` (rohlikMatch 30, rohlikFillCart 10, rohlikOAuthStart 10, rohlikOAuthFinish 10, rohlikStatus 60, rohlikCart 60, rohlikCheckout 60, rohlikTimeslots 120, rohlikCheckoutUpdate 150, rohlikCheckoutLink 30, rohlikDeliveryOptions 30, rohlikSyncOrders 60, rotateJoinCode 20), `u/{uid}/{fn}` (joinHousehold 10, createHousehold 5), `ip/{ip}/registerAccount` (5; cleared nightly). Input validators are in `functions/src/validate.js`. `maxInstances`: callables 3, scheduler 1.

### Security rules (`database.rules.json`, tests in `test/rules/`)

Default deny. `users/$uid`: self only, keys `nickname` (≤ 32) and `householdId` (only a household that already lists the user as a member). `joinCodes/$code`: single-key read for signed-in users, no client writes. `households/$hid`: read for members; the household root, `owner`, `joinCode`, `members` and `rohlik` are server-only (creating, joining, removing go through callables); the owner may write `name` (1–40); members may write validated `recipes`, `plan`, `orders` (`by` = self), `pantry`, `regulars`, `productPrefs` (strings ≤ 200, `imageUrl` https ≤ 500, `count` integer ≥ 1, `lastAt` number, `by` = self), `settings` (incl. `shop` and `delivery`: integer `addressId`, strings ≤ 80/60/300, enums for `window` / `lead` / `packaging`, `paymentId` `^[A-Z0-9_]{1,40}$`, no other keys), `orders/*/rohlikOrderId` (integer ≥ 1), append-only `activity` (`by` = self) and their own `pushTokens/{uid}`. `householdPhotos/$hid`: members only, JPEG data URLs < 400 000 chars; `householdThumbs/$hid`: members only, JPEG data URLs < 45 000 chars. `rohlikCredentials`, `rohlikOAuthClient`, `rohlikOAuthPending`, `rateLimits`, `householdIndex`: admin only. Every new client write path must satisfy these rules – add a case to `test/rules/database.rules.test.js`.

### Hosting

`firebase.json` sets security headers for all paths (CSP without inline scripts – the committed `.env` has `INLINE_RUNTIME_CHUNK=false`; X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy) plus no-cache for HTML and immutable caching for `/static/**`. A new external origin (fonts, APIs, images, scripts) must be added to the CSP. The hosting emulator does not apply `headers`. The messaging service worker only navigates to same-origin URLs.
